# یادداشت‌های انتشار

برای هر نسخه یک فایل با اسم tag بساز (مثلاً `v1.3.0.md`) و قبل از push کردن tag
commit کن. job `publish-release` همین متن را توضیح GitHub Release می‌کند و اپ آن را
در پنجره‌ی «به‌روزرسانی» زیر «تغییرات» نشان می‌دهد. اگر فایل نباشد، GitHub فهرست
PRها را خودش می‌سازد (انگلیسی).

کوتاه و برای کاربر بنویس، مثلاً:

```markdown
- اتصال سرویس‌های تونل درست شد
- به‌روزرسانی از داخل برنامه
```
